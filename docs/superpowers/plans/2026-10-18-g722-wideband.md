# G.722 Wideband Codec Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TTS calls negotiate G.722 wideband audio with GoTo (offer `g722 pcma`, encode with whichever the 200 OK answer picks), falling back to today's G.711 by construction.

**Architecture:** A pure-Python ITU-T G.722 encoder in a new `sip/g722.py`; `sip/audio.py` resamples to the codec's rate (16 kHz for g722); `sip/messages.py` offers multiple codecs in one SDP m= line; `sip/call.py` parses the answered payload types and encodes after the answer instead of before the INVITE. `sip/rtp.py` is untouched (G.722's RTP clock is 8 kHz per RFC 3551, so 160 bytes / 160 ticks per 20 ms frame holds for both codecs).

**Tech Stack:** Python ≥3.12 stdlib only (`audioop`/`audioop-lts` for G.711 + resampling), pytest + pytest-asyncio against `tests/sip/fake_goto.py`.

**Spec:** `docs/superpowers/specs/2026-10-18-g722-wideband-design.md`

## Global Constraints

- Python ≥3.12 and 3.13 both pass; `audioop` import stays wrapped (audioop-lts on 3.13+).
- **No new runtime dependency** — the G.722 codec is pure stdlib Python.
- Full suite green under `.venv/bin/python -m pytest -W error` after every task.
- Work on branch `feat/g722`; main is PR-only (required checks: test 3.12 + 3.13).
- Conventional Commits; end commit messages with the session's attribution lines.
- Default codec offer is `("g722", "pcma")`; PCMU stays opt-in.
- G.722: RTP payload type 9, rtpmap **`G722/8000`** (RFC 3551 quirk — never 16000), 64 kbit/s mode, one output byte per two 16 kHz input samples.

## Review Focus

1. Answer m= line listing `telephone-event` (101) first — the codec chooser must skip non-codec payload types, not stream "codec 101". → test in Task 4.
2. Answer containing only payload types we never offered (e.g. 18/G729 from a misbehaving middlebox) — fall back to the first offered codec, don't crash. → test in Task 4.
3. 44.1 kHz stereo TTS WAV through the g722 path — downmix + resample to 16 kHz, payload ≈ duration × 8000 bytes. → test in Task 2.
4. Odd sample count into `g722.encode` — trailing sample dropped, no exception. → test in Task 1.
5. `codecs=()` or an unknown codec name in `call_and_play` — immediate `ValueError` before any network I/O. → test in Task 4.

### Task 4: Answer-driven codec selection (`sip/call.py` + fake server)

**Files:**
- Modify: `src/aiogotoconnect/sip/call.py`, `tests/sip/fake_goto.py`
- Test: `tests/sip/test_call.py`

**Interfaces:**
- Consumes: `wav_pcm` / `pcm_to_payload` (Task 2), `PT_CODECS`, `CODEC_PAYLOADS`, `build_invite(codecs=...)` (Task 3).
- Produces (public API change, 0.3.0):
  - `GoToVoice.call_and_play(number, wav_bytes, *, ring_timeout=25.0, repeat=1, codecs: Sequence[str] = ("g722", "pcma")) -> CallResult` — replaces `codec: str = "pcma"` (callers pass `codecs=("pcmu",)` for old opt-in).
  - `_remote_media(sdp) -> tuple[str, int, tuple[int, ...]]` — ip, port, answered payload types from the m= line.
  - `_codec_from_answer(pts: Sequence[int], offered: Sequence[str]) -> str` — first pt that maps via `PT_CODECS` to an offered codec; none match → `offered[0]`.
  - `_Call.invite(ring_timeout, codecs: Sequence[str])`.
- Flow change in `call_and_play`: upfront `pcm, rate = wav_pcm(wav_bytes)` and validate every name in `codecs` (empty/unknown → `ValueError`) **before** `tp.connect()`; after the 200 OK, `codec = _codec_from_answer(...)`, `payload = pcm_to_payload(pcm, rate, codec)`, stream with that codec's pt.

**fake_goto.py changes:** `answer_pt: int | None = None` constructor option (force the answered codec; default behavior: first offered pt among {0, 8, 9}); `_answer` names `{0: "PCMU", 8: "PCMA", 9: "G722"}`; the RTP validity filter accepts the agreed `self._pt` instead of hard-coded PT 8.
